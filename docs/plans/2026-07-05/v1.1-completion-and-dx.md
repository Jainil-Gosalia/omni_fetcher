# v1.1 — Contract Completion & Developer Experience

**Status:** planned
**Target version:** 1.1.0 (minor, no breaking changes)
**Prerequisites:** v1.0.0 shipped (canonical contract, 21 connectors, green CI, PyPI trusted publishing)

## Goal

Finish what 1.0 started and make the v1 API pleasant to adopt. Three threads:
complete the contract features that shipped as seams (zoom), close the quality
gaps 1.0 left open (4 untested connectors, no resilience story), and remove
the adoption friction (hand-built registries, legacy-only CLI and docs).

Explicitly **not** in 1.1 (each is PRD-sized, deferred to 1.2+):
streaming/unbounded connectors, LLM-imposed structure (Phase 2),
model-based extraction (OCR/transcription), tamper-evidence verification.

**Namespace decision (recorded for 2.0):** `omni_fetcher.v1` remains the
canonical import path through all of 1.x. Promoting the v1 surface to the
top level is blocked until the legacy layer is removed: the top-level
namespace is occupied by legacy classes with directly colliding names
(`OmniFetcher`, `BaseFetcher`) and its `__init__` eagerly imports every
legacy fetcher. In 2.0, the legacy layer is deleted, the v1 surface moves to
`omni_fetcher` (`from omni_fetcher import Success, Text, OmniFetcher`;
`omni_fetcher.connectors.*`), and `omni_fetcher.v1` stays as a thin alias
for at least one major cycle so 1.x code migrates by deleting `.v1`.

## Phases

Each phase is an independently shippable vertical slice; order minimizes
rework (the registry lands first because the CLI and docs build on it).

### Phase 1 — `builtin_registry()` + legacy deprecation signal

The single highest-leverage DX gap: today every host hand-assembles 21
`SourceDefinition`s before the orchestrator does anything.

- `omni_fetcher.v1.builtin_registry()` returns a `FrozenRegistry` with all
  built-in connectors registered under their real URI patterns and sane
  priorities. Connectors whose optional extra is missing (office / jira /
  confluence) are skipped with a debug-level note — never an import error.
  Import of connector modules is lazy so `import omni_fetcher.v1` stays light.
- Export `RegistryBuilder`, `OmniFetcher` (orchestrator), and
  `builtin_registry` from `omni_fetcher.v1` — they are the wiring API and
  currently require deep-path imports.
- Emit `DeprecationWarning` on first import of the legacy layer
  (`omni_fetcher.fetcher`, `omni_fetcher.fetchers.*`), pointing at the
  migration guide. Announce removal target (2.0) in the warning text and
  CHANGELOG. Tests assert the warning fires exactly once and that
  `-W error::DeprecationWarning` does not break the v1 path.
- README orchestrator example updated to the one-liner.

**Acceptance:** `OmniFetcher(builtin_registry())` routes every connector's
documented URI shapes; a minimal install (no extras) still imports and routes
the core connectors; legacy import warns once.

### Phase 2 — Close the connector test gap (notion, linear, confluence, youtube)

Four connectors shipped with no v1 behavior tests. Mirror the established
suite pattern (httpx MockTransport / stubbed clients, external behavior only):

- `tests/v1/test_connector_notion.py` — page and database URIs, BearerAuth
  reaches the request, descriptive fields in `source_extra["notion"]`,
  NOT_FOUND / AUTH_FAILED as typed errors.
- `tests/v1/test_connector_linear.py` — issue / team / project routes,
  BearerAuth + ApiKeyAuth accepted, GraphQL payload mapping.
- `tests/v1/test_connector_confluence.py` — page / space routes, BasicAuth
  and BearerAuth client shapes, storage-format body → Text atom.
- `tests/v1/test_connector_youtube.py` — metadata mapping via a stubbed
  yt_dlp, no network.

**Acceptance:** all 21 connectors have a v1 behavior suite; coverage of
`omni_fetcher/v1/connectors/` reported in CI does not regress below the
current baseline.

### Phase 3 — Make zoom real

The pure machinery (`ZoomSpec`, `DepthLevel`, resolver, `prune_to_zoom`)
shipped in 1.0; no connector honors it. Two halves, cheapest first:

1. **Central pruning (all connectors at once).** `BaseFetcher.fetch()` (and
   the orchestrator pass-through) applies `prune_to_zoom` to every returned
   tree when a `ZoomSpec` is supplied. Coarser-than-natural requests
   (`WHOLE`, `SECTION` on deep trees) now work everywhere with zero
   connector changes.
2. **Deeper-than-natural decomposition (per connector, text first).** A
   shared pure helper decomposes `Text` atoms into `SECTION` / `PARAGRAPH` /
   `SENTENCE` child nodes; wire it into the text-bearing connectors
   (local_file, http_url, pdf, docx, pptx). Non-text atom kinds keep
   returning their natural granularity and record an honest
   `unsupported`-style gap only when a finer level was explicitly requested.

**Acceptance:** contract tests assert (a) pruning: `WHOLE` yields a childless
node for every connector fixture; (b) expansion: a multi-paragraph document
fetched at `PARAGRAPH` yields one child per paragraph with content
concatenation equal to the natural fetch; (c) determinism: same input + spec
→ identical tree.

### Phase 4 — Stateless resilience helpers

v1 classifies transient failures (`ErrorKind.TRANSIENT`, `RATE_LIMITED`) but
offers nothing to act on them. Keep it host-side and stateless:

- `omni_fetcher.v1.retry.RetryPolicy` — frozen config (max attempts, backoff
  base/cap, jitter, retryable `ErrorKind`s; defaults: TRANSIENT +
  RATE_LIMITED).
- `await fetch_with_retry(fetcher_or_omni, uri, *, policy, auth, zoom)` —
  pure wrapper: re-invokes on retryable `Error` results, returns the final
  `Result`. Never retries `Partial` (data was delivered) and never raises.
- Audit connectors' error classification so retryable conditions actually map
  to retryable kinds (HTTP 429/5xx → RATE_LIMITED/TRANSIENT consistently).

**Acceptance:** unit tests with scripted fetchers prove attempt counting,
backoff sequence (injectable sleeper — no real waiting), non-retryable kinds
pass through untouched, and concurrent use shares no state.

### Phase 5 — v1 CLI

`omni-fetcher` currently drives only the legacy layer. Add a v1 path without
breaking existing commands:

- `omni-fetcher fetch <uri> [--auth-type bearer --token-env VAR ...]
  [--zoom text=paragraph] [--json | --tree]` — wires
  `OmniFetcher(builtin_registry())`, prints either pretty rich tree
  (metadata core + atom summaries + `source_extra`) or `model_dump_json()`.
- Credentials accepted via env-var *names* only (`--token-env`), never raw
  secrets in argv; nothing is persisted.
- Exit codes: 0 success, 1 error result, 2 usage error. `Partial` exits 0
  with gaps rendered on stderr.

**Acceptance:** CLI test suite drives `fetch` against local-file and stubbed
HTTP fixtures; legacy commands unchanged.

### Phase 6 — Docs refresh + release

- Rewrite `docs/index.md`, `docs/fetchers.md`, `docs/auth.md` to the v1 API
  (same verified-example discipline as the README rewrite; legacy content
  moves under a clearly-labeled legacy heading or into `docs/legacy/`).
- CHANGELOG `## [1.1.0]` entry; README touch-ups for the new surface
  (`builtin_registry`, retry, CLI, zoom).
- Ship: merge → GitHub Release `v1.1.0` → trusted publishing to PyPI
  (also refreshes the PyPI project page with the 1.0 README rewrite).

**Acceptance:** all six CI jobs green; `pip install omni-fetcher==1.1.0`
serves the new surface; PyPI page shows the v1-first README.

## Risks

- **Zoom expansion quality** (Phase 3.2): sentence/paragraph splitting of
  arbitrary text is heuristic. Mitigation: ship SECTION/PARAGRAPH first
  (structure the sources already expose), treat SENTENCE as best-effort, and
  keep the splitter a pure, versioned function so behavior changes are
  reviewable.
- **Lazy builtin registry vs. import cost**: registering 21 connectors must
  not import heavy deps eagerly (yt_dlp is slow). Mitigation: definitions
  carry module paths; the fetcher class resolves on first route.
  (If `SourceDefinition.fetcher_class` can't stay lazy cleanly, an internal
  `_LazyDefinition` that resolves at `resolve()` time keeps the public type
  unchanged.)
- **DeprecationWarning noise** for legacy-only users: warn once per process,
  include the silencing recipe in the message.
